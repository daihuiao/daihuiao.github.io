# Chrome 扩展 MV3 项目阅读笔记

这篇笔记整理的是阅读 `sub2api reoauth` 这个 Chrome 扩展时遇到的一组基础问题。重点不是 Chrome 扩展 API 的完整手册，而是从一个实际项目里理解：`manifest.json`、`background`、`service worker`、`side panel`、`content script`、消息通信和存储分别在干什么。

## 应该从哪里开始看

Chrome 扩展项目通常从 `manifest.json` 开始看。

`manifest.json` 是扩展的总配置文件，它告诉 Chrome：

- 这个扩展用的是哪一代规范
- 后台入口文件在哪里
- UI 入口是什么
- 需要哪些权限
- 是否有 content script
- 是否有 popup、side panel、options page 等页面

这个项目里的核心配置大概是：

```json
{
  "manifest_version": 3,
  "background": {
    "service_worker": "background/background.js",
    "type": "module"
  },
  "side_panel": {
    "default_path": "sidepanel/sidepanel.html"
  },
  "permissions": [
    "sidePanel",
    "storage",
    "scripting",
    "tabs",
    "webNavigation"
  ],
  "optional_host_permissions": [
    "http://*/*",
    "https://*/*"
  ]
}
```

读这个文件时，先建立一张运行结构图：

```text
manifest.json
  |
  +-- side_panel.default_path -> sidepanel/sidepanel.html
  |
  +-- background.service_worker -> background/background.js
  |
  +-- permissions -> 这个扩展能调用哪些 Chrome API
```

所以这个项目可以按这个顺序读：

1. `manifest.json`
2. `sidepanel/sidepanel.html`
3. `sidepanel/sidepanel.js`
4. `background/background.js`
5. `background/sub2api-client.js`
6. `content/openai-login-learning.js`
7. `content/qq-mail-learning.js`
8. `test/*.test.mjs`

一句话概括：

```text
sidepanel 是用户操作台
background 是后台调度中心
content script 是注入网页里干活的脚本
SUB2API 是外部服务
```

## MV3 是什么

MV3 是 Manifest Version 3，也就是 Chrome 扩展的第三代规范。

它影响这个项目最明显的几点：

- 后台脚本使用 service worker
- 动态注入脚本使用 `chrome.scripting`
- 权限管理更严格
- 后台逻辑更偏事件驱动

这个配置：

```json
{
  "manifest_version": 3
}
```

表示这个扩展按 MV3 规则运行。

## service worker 是什么角色

在 MV3 里，background 入口通常就是 service worker：

```json
"background": {
  "service_worker": "background/background.js",
  "type": "module"
}
```

可以把 `background/background.js` 理解成这个插件的后台调度中心。

它负责：

- 接收 side panel 发来的消息
- 调用 SUB2API
- 打开新标签页
- 激活或切换标签页
- 注入 content script
- 监听 OAuth 的 localhost 回调
- 把临时状态写入 `chrome.storage.session`

它和传统服务器有点像，都是负责调度和处理请求。但它不是一个一直运行的服务进程。MV3 service worker 是事件驱动的，Chrome 会按需唤醒它，空闲后可能把它停掉。

所以不能把重要流程状态只放在普通 JS 变量里。这个项目会把重要状态放到 Chrome 扩展存储里。

## background 是干嘛的

`background/` 文件夹放的是后台逻辑。

这个项目里主要有三个文件：

```text
background/background.js
background/sub2api-client.js
background/openai-learning.js
```

其中：

- `background/background.js` 是插件后台入口，负责消息分发和 Chrome API 调度
- `background/sub2api-client.js` 封装 SUB2API 请求
- `background/openai-learning.js` 放可测试的纯逻辑，比如验证码规范化、localhost URL 判断

为什么要单独放一个 `background/` 文件夹？

因为 Chrome 扩展的不同部分运行在不同环境里：

| 部分 | 跑在哪里 | 主要职责 |
| --- | --- | --- |
| `sidepanel` | 扩展自己的侧边栏页面 | 显示 UI，收集输入，发消息 |
| `background` | 扩展后台 service worker | 调度、请求、管理标签页、监听事件 |
| `content` | 被注入的网站页面里 | 读写网页 DOM |

可以这样理解：

```text
sidepanel = 控制台
background = 调度中心
content script = 伸进网页里的手
```

## 插件只有 side panel 吗

不是。

Chrome 扩展有多种 UI 形式。

常见的有：

| 类型 | manifest 配置 | 特点 |
| --- | --- | --- |
| action popup | `action.default_popup` | 点击扩展图标弹出一个小浮窗，失焦后关闭 |
| side panel | `side_panel.default_path` | 浏览器侧边栏，适合长流程和持续状态 |
| options page | `options_page` | 设置页面 |
| content script UI | content script 自己插 DOM | 直接在网页上显示按钮、浮窗、面板 |
| devtools page | `devtools_page` | 浏览器开发者工具里的扩展面板 |

你记得的“点击图标出现一个浮动窗口”，通常是 popup：

```json
"action": {
  "default_popup": "popup/popup.html",
  "default_title": "插件名称"
}
```

这个项目用 side panel，是因为它有 0 到 10 步流程、账号表格、验证码、回调地址这些持续状态。popup 点到外面就关，不太适合这种长流程。

## `chrome.tabs.update` 是切换 tab 还是跳转页面

两种都可以，看传什么参数。

激活某个 tab：

```js
await chrome.tabs.update(tabId, { active: true });
```

这会把浏览器前台切到这个标签页。

让某个 tab 跳转到新 URL：

```js
await chrome.tabs.update(tabId, { url: "https://example.com" });
```

这个项目里的 `activateTab(tabId)` 用的是：

```js
await chrome.tabs.update(tabId, { active: true });
```

所以它的作用是切换到指定标签页，不是改 URL。

## `chrome.webNavigation` 是什么

`chrome.webNavigation` 是 Chrome 扩展提供的页面导航监听 API。

它可以监听某个 tab 什么时候开始跳转、跳转是否提交、是否完成、是否失败等。

这个项目用到了两个事件：

```js
chrome.webNavigation?.onBeforeNavigate?.addListener((details) => {
  captureLocalhostCallback(details).catch(() => {});
});

chrome.webNavigation?.onCommitted?.addListener((details) => {
  captureLocalhostCallback(details).catch(() => {});
});
```

含义是：

- `onBeforeNavigate`：页面即将开始跳转
- `onCommitted`：导航已经提交

为什么 OAuth 流程要监听这个？

OpenAI OAuth 授权成功后，浏览器会跳到一个 localhost 回调地址，例如：

```text
http://localhost:1455/auth/callback?code=xxx&state=yyy
```

即使本机没有真的启动 `localhost:1455` 服务，浏览器也会尝试导航到这个 URL。扩展可以通过 `webNavigation` 在跳转过程中拿到完整 URL。

项目里会进一步过滤：

```js
if (details?.frameId !== 0) return;
if (!isLocalhostCallbackUrl(details?.url)) return;
```

`frameId === 0` 表示主页面，不是 iframe。这样可以避免把页面内部 iframe 的跳转误认为 OAuth 回调。

## `chrome.storage.session` 和 `chrome.storage.local`

这是 Chrome 扩展自己的存储 API，不是网页里的 `localStorage`。

### `chrome.storage.local`

`local` 是持久存储。

示例：

```js
await chrome.storage.local.set({
  loginEmail: "user@example.com"
});

const saved = await chrome.storage.local.get(["loginEmail"]);
```

特点：

- 关闭侧边栏后还在
- 关闭浏览器后通常还在
- 适合保存配置和表单字段

这个项目用它保存：

- SUB2API 地址
- SUB2API 管理员账号
- SUB2API 管理员密码
- OpenAI 登录邮箱
- OpenAI 登录密码
- 分组名

### `chrome.storage.session`

`session` 是会话级临时存储。

示例：

```js
await chrome.storage.session.set({
  openAiLearningVerificationCode: "123456"
});

const saved = await chrome.storage.session.get("openAiLearningVerificationCode");
```

特点：

- 当前浏览器会话内可用
- 关闭浏览器后会丢
- 适合保存临时流程状态

这个项目用它保存：

- 当前 OpenAI 授权 tab id
- QQ 邮箱基线
- 验证码
- OAuth localhost 回调 URL
- 第 0 步生成的重授权上下文

简单记：

```text
storage.local   = 长期配置
storage.session = 本次流程临时状态
```

MV3 service worker 可能被 Chrome 暂停，所以项目不能只依赖内存变量保存流程状态。

## content script 注入是什么

background 不能直接操作网页 DOM。

比如 OpenAI 页面里有：

```html
<input type="email">
<button>Continue</button>
```

`background/background.js` 看不到这些元素，也不能直接：

```js
document.querySelector("input[type=email]")
```

因为 background 运行在扩展后台，不运行在网页里。

所以需要把 content script 注入到网页 tab 中：

```js
await chrome.scripting.executeScript({
  target: { tabId },
  files: ["content/openai-login-learning.js"]
});
```

这可以理解成 Chrome 把这个 JS 文件放到指定网页旁边执行。

它很像“给网页加了一个 JS 文件”，但不完全等同于网页自己的 `<script>`。content script 运行在隔离环境里：

- 可以访问和修改网页 DOM
- 可以点击按钮、填写输入框
- 可以和扩展通信
- 一般不能直接访问网页自己的 JS 全局变量

这个项目的流程是：

```text
background 注入 content/openai-login-learning.js
  |
  v
content script 注册 chrome.runtime.onMessage 监听
  |
  v
background 用 chrome.tabs.sendMessage(tabId, message) 发命令
  |
  v
content script 根据 message.action 执行填邮箱、填密码、点按钮等动作
```

对应代码结构是：

```js
// background/background.js
await chrome.scripting.executeScript({
  target: { tabId },
  files: ["content/openai-login-learning.js"]
});

const response = await chrome.tabs.sendMessage(tabId, {
  type: "RUN_OPENAI_LEARNING_STEP",
  action,
  value: message.value || {}
});
```

content script 里接收：

```js
chrome.runtime.onMessage.addListener((message, _sender, sendResponse) => {
  if (message?.type !== "RUN_OPENAI_LEARNING_STEP") return undefined;

  try {
    sendResponse({
      ok: true,
      result: runLearningStep(message.action, message.value || {})
    });
  } catch (error) {
    sendResponse({
      ok: false,
      error: String(error?.message || "页面步骤未完成。")
    });
  }

  return true;
});
```

## 为什么需要 `"permissions": ["scripting"]`

这个权限允许扩展调用：

```js
chrome.scripting.executeScript(...)
```

没有 `scripting` 权限，插件就不能动态注入 JS 文件到网页中。

如果不用 `scripting`，通常可以在 manifest 里静态声明 content scripts：

```json
"content_scripts": [
  {
    "matches": [
      "https://chatgpt.com/*",
      "https://*.openai.com/*"
    ],
    "js": ["content/openai-login-learning.js"]
  }
]
```

但这种方式的特点是：

- 页面加载时就自动注入
- 更适合长期需要在某些网页运行的插件
- 不如动态注入适合“用户点击一步才执行一步”的教学流程

这个项目选择动态注入，是为了让脚本只在用户主动操作时运行。

## `chrome.runtime.sendMessage` 发给谁

这个非常像 ROS 里的 topic/service 通信。

Chrome 扩展里很多部分不能直接互相调用函数。比如 side panel 不能直接调用 background 里的 `handleMessage()`，background 也不能直接调用网页里的 `runLearningStep()`。

所以它们用消息通信。

### side panel 发给 background

side panel 里：

```js
chrome.runtime.sendMessage({
  type: "RUN_OPENAI_LEARNING_STEP",
  action: "fill-email",
  value: { email: "xxx@example.com" }
});
```

background 里：

```js
chrome.runtime.onMessage.addListener((message, _sender, sendResponse) => {
  handleMessage(message)
    .then((payload) => {
      sendResponse({ ok: true, ...payload });
    })
    .catch((error) => {
      sendResponse({ ok: false, error: String(error.message) });
    });

  return true;
});
```

`chrome.runtime.sendMessage(...)` 发到扩展运行时消息总线。扩展里的 `chrome.runtime.onMessage` 监听器有机会收到。

这个项目里，主要由 background 接收 side panel 发出的业务消息。

### background 发给指定 tab 的 content script

background 给网页里的 content script 发消息时，用的是：

```js
chrome.tabs.sendMessage(tabId, {
  type: "RUN_OPENAI_LEARNING_STEP",
  action: "fill-email",
  value: { email: "xxx@example.com" }
});
```

这里多了一个 `tabId`，所以目标很明确：发给指定 tab 里的 content script。

区别可以这样记：

```text
chrome.runtime.sendMessage(...)  = 发给扩展内部
chrome.tabs.sendMessage(tabId)   = 发给指定网页 tab 里的 content script
```

### 靠什么区分具体业务

靠消息里的 `type` 字段。

比如这个项目的消息类型有：

```text
QUERY_REAUTH_CANDIDATES
OPEN_FIRST_OPENAI_REAUTH
SNAPSHOT_QQ_MAIL_BASELINE
FETCH_QQ_OPENAI_LOGIN_CODE
RUN_OPENAI_LEARNING_STEP
ARM_OPENAI_CALLBACK_CAPTURE
GET_OPENAI_CALLBACK_CAPTURE
CLEAR_OPENAI_CALLBACK_CAPTURE
SUBMIT_OPENAI_REAUTH_CALLBACK
```

这就很像：

```text
topic/service 名 = message.type
参数 = message 里的其他字段
handler = onMessage 里的分支
```

所以读这种项目时，不只看函数调用，还要看消息协议。

## `handleMessage(message)` 是什么

`handleMessage(message)` 是后台消息分发器。

它大概长这样：

```js
async function handleMessage(message = {}) {
  if (message.type === "QUERY_REAUTH_CANDIDATES") {
    return {
      result: await sub2ApiClient.queryReauthCandidates(message.connection || {})
    };
  }

  if (message.type === "RUN_OPENAI_LEARNING_STEP") {
    const result = await runOpenAiLearningStep(message);
    return { result };
  }

  return null;
}
```

它被 `chrome.runtime.onMessage.addListener(...)` 调用：

```js
chrome.runtime.onMessage.addListener((message, _sender, sendResponse) => {
  handleMessage(message)
    .then((payload) => sendResponse({ ok: true, ...payload }))
    .catch((error) => sendResponse({ ok: false, error: String(error.message) }));

  return true;
});
```

这条主线非常关键：

```text
onMessage 收到消息
  |
  v
handleMessage(message)
  |
  v
根据 message.type 分派到具体函数
```

## `getActiveTabId()` 是什么

它负责找当前浏览器窗口里正在激活的 tab：

```js
async function getActiveTabId() {
  const [tab] = await chrome.tabs.query({
    active: true,
    lastFocusedWindow: true
  });

  if (!Number.isInteger(tab?.id)) {
    throw new Error("没有可操作的当前标签页。");
  }

  return tab.id;
}
```

这个项目在执行 OpenAI 页面步骤时会调用它：

```js
const tabId = await getActiveTabId();
```

然后把 `content/openai-login-learning.js` 注入到这个 tab。

## `runOpenAiLearningStep(message)` 是什么

这个函数负责执行 OpenAI 页面上的学习步骤。

它做了几件事：

1. 检查 `message.action` 是否是允许的动作
2. 获取当前激活 tab
3. 记录这个 tab 是 OpenAI 授权 tab
4. 注入 `content/openai-login-learning.js`
5. 给这个 tab 里的 content script 发送命令
6. 返回 content script 的执行结果

简化后：

```js
async function runOpenAiLearningStep(message = {}) {
  const action = String(message.action || "");

  const tabId = await getActiveTabId();

  await chrome.scripting.executeScript({
    target: { tabId },
    files: ["content/openai-login-learning.js"]
  });

  const response = await chrome.tabs.sendMessage(tabId, {
    type: "RUN_OPENAI_LEARNING_STEP",
    action,
    value: message.value || {}
  });

  return response.result || {};
}
```

它不是用户直接调用的，而是 message handler 调用的：

```text
sidepanel 点击按钮
  |
  v
chrome.runtime.sendMessage({ type: "RUN_OPENAI_LEARNING_STEP", ... })
  |
  v
background 的 onMessage
  |
  v
handleMessage(message)
  |
  v
runOpenAiLearningStep(message)
```

## 怎么读 JS 项目，不想全靠全局搜索怎么办

写 JS 的人不是所有东西都只能靠全局搜索。正常的静态调用、模块导入、类方法，IDE 应该能跳转。

但 Chrome 扩展、前端、Electron、VS Code 插件这类项目里，有很多事件驱动和消息驱动代码。它们不是普通函数直接调用，而是：

```text
发送一条消息
另一个地方监听消息
根据字符串 type 分发
```

这种调用链 IDE 很难完全推断。

读这类 JS 项目时，可以按三种线索看：

### 1. 文件入口

先从 manifest、package、路由配置、HTML script 标签找入口。

这个项目的入口是：

```text
manifest.json
sidepanel/sidepanel.html
background/background.js
```

### 2. import/export

看模块之间的静态依赖：

```js
import { createSub2ApiClient } from "./sub2api-client.js";
```

这种 IDE 一般能跳。

### 3. 事件名和消息 type

看事件驱动协议：

```js
chrome.runtime.onMessage.addListener(...)
chrome.runtime.sendMessage({ type: "RUN_OPENAI_LEARNING_STEP" })
chrome.tabs.sendMessage(tabId, { type: "RUN_OPENAI_LEARNING_STEP" })
```

这部分通常要搜 `type` 字符串。

常用搜索方式：

```bash
rg -n "RUN_OPENAI_LEARNING_STEP"
rg -n "OPEN_FIRST_OPENAI_REAUTH"
rg -n "chrome.runtime.onMessage"
rg -n "chrome.tabs.sendMessage"
```

这不表示 JS 项目低级，而是因为这里的调用关系本来就是运行时事件总线，不是静态函数调用。

和 ROS 类比的话：

```text
函数调用          = 直接调用方法
message.type      = topic/service 名
sendMessage       = 发布/调用
onMessage         = 订阅/处理
handleMessage     = 路由分发
```

## 这个项目的主调用链

把整个项目压缩成一条主线：

```text
用户打开 side panel
  |
  v
sidepanel/sidepanel.html 加载 sidepanel/sidepanel.js
  |
  v
用户点击按钮
  |
  v
sidepanel.js 调用 chrome.runtime.sendMessage(...)
  |
  v
background/background.js 的 chrome.runtime.onMessage 收到消息
  |
  v
handleMessage(message) 根据 message.type 分发
  |
  +-- 查询账号 -> background/sub2api-client.js
  |
  +-- 打开重授权页 -> chrome.tabs.create(...)
  |
  +-- 执行 OpenAI 页面动作
|  |
  |     +-- chrome.scripting.executeScript(...)
  |     +-- chrome.tabs.sendMessage(tabId, ...)
  |     +-- content/openai-login-learning.js 操作 DOM
  |
  +-- 从 QQ 邮箱取码
|  |
  |     +-- 激活 QQ 邮箱 tab
  |     +-- 注入 content/qq-mail-learning.js
  |     +-- 读取新验证码邮件
  |
  +-- 监听 localhost 回调
|  |
  |     +-- chrome.webNavigation.onBeforeNavigate
  |     +-- chrome.webNavigation.onCommitted
  |
  +-- 推送回 SUB2API
        |
        +-- exchange code
        +-- update account
        +-- clear error
```

读懂这条线，再回头看每个函数，项目结构就清楚很多。

```
